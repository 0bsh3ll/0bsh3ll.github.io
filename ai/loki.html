Loki — A Local AI Agent That Actually Does Things

📅 2025-04-29 ⏱ 12 min read ⚙️ Local LLM agent harness
A ~200-line Python CLI agent that wraps a local Ollama model and gives it tools — file I/O, code editing, web search — through a simple text protocol. No cloud, no API keys. Responses stream token-by-token. The LLM never touches your filesystem directly: it asks for things to happen, and the harness makes them happen. Full Loki code on GitHub ↗

01 — The Problem

Cloud AI assistants are powerful but they phone home with every keystroke. Local LLMs are private but dumb in isolation — they can't search the web, read your files, or edit code. The missing piece isn't a smarter model, it's a harness that gives a local model real capabilities through tools.

The goal: type a question in your terminal, get a grounded answer. If the model needs to search the web, it searches. If it needs to read a file, it reads. If it needs to create one, it creates. All visible in your terminal, all local, all under your control.

Built on the architecture described in The Emperor Has No Clothes — the idea that you don't need a massive framework, just a clean loop and a text protocol.

02 — Architecture

Loki follows the harness pattern: a thin Python loop wraps the LLM and gives it tools through a text protocol. Every module is independent — swap the LLM provider by replacing one file, add tools by dropping Python files into a folder.

01
System Prompt Injection
Tool schemas auto-generated from function signatures and docstrings, injected into the system prompt at startup.
02
Streaming Response
Ollama streams NDJSON token-by-token. StreamPrinter suppresses tool: lines live so the user only sees the answer.
03
Tool Execution
Parser extracts tool calls from accumulated text, executes via the decorator-based registry, feeds results back.
04
Forced Search
If the model tries to answer a "current/latest" question from memory without searching, the harness forces a retry through web_search.
03 — The Code

Agent Loop

loki.py Python 
# Simplified core loop — the full version handles
  # streaming, thinking-block suppression, and retries

  from llm import chat_stream
  from tool_parser import extract_tool_calls
  from tool_registry import execute_tool
  from system_prompt import build_system_prompt

  history = []
  system = build_system_prompt()  # personality + tool schemas

  while True:
      user_input = input("You: ")
      history.append({"role": "user", "content": user_input})

      # Stream the response, printing tokens live
      response = chat_stream(system, history)

      # Check for tool calls in the response
      tool_calls = extract_tool_calls(response)

      if tool_calls:
          for call in tool_calls:
              result = execute_tool(call.name, call.args)
              # Feed result back and let the model answer
              history.append({
                  "role": "assistant",
                  "content": format_tool_result(call, result)
              })
              response = chat_stream(system, history)

      history.append({"role": "assistant", "content": response})

Tool Registration — Drop a File, Get a Tool

tools/web_search.py Python 
from typing import Any, Dict
  from tool_registry import register_tool
  from ddgs import DDGS

  @register_tool("web_search")
  def web_search(query: str) -> Dict[str, Any]:
      """Search the web and return top results.
      :param query: The search query string.
      :return: A dict with search results.
      """
      results = DDGS().text(query, max_results=3)
      return {"results": results}
💡
That's all it takes. Drop a .py file in tools/, decorate the function with @register_tool, and restart Loki. The schema generator reads the docstring for the description and the type annotations for parameter shapes. Auto-discovered via pkgutil.iter_modules.

StreamPrinter — Live Token Suppression

loki.py — StreamPrinter Python 
# StreamPrinter is a state machine that:
  # • Holds the first ~5 chars of every new line
  # • Decides "tool line vs prose"
  # • Suppresses any line whose prefix is "tool:"
  # • Eats <think>...</think> spans (rolling tail buffer)
  # • Emits the "Loki:" prefix lazily — a tool-only
  #   reply leaves no orphan label

  class StreamPrinter:
      def __init__(self):
          self.line_buffer = ""
          self.suppressing = False
          self.label_emitted = False
          self.think_depth = 0

      def feed(self, token: str):
          for ch in token:
              if ch == '\n':
                  self._flush_line()
                  self.line_buffer = ""
                  self.suppressing = False
              else:
                  self.line_buffer += ch
                  if len(self.line_buffer) == 5:
                      self._decide()

      def _decide(self):
          if self.line_buffer.strip().lower().startswith("tool:"):
              self.suppressing = True
          else:
              if not self.label_emitted:
                  print("Loki: ", end="", flush=True)
                  self.label_emitted = True
              print(self.line_buffer, end="", flush=True)
04 — Built-in Tools
Tool What it does
read_file Reads a file and returns its contents
list_files Lists files and directories in a path
edit_file Creates new files or does find-and-replace edits
web_search Searches the web via DDGS — no API key, aggregates DuckDuckGo, Bing, Google

Adding a new tool is a one-file operation. Drop a Python file in tools/ with a @register_tool decorator — no imports to update, no config to edit. On restart, pkgutil.iter_modules discovers it, the schema generator reads the function signature, and it's injected into the system prompt.

06 — Personality & Guardrails

Loki's personality is defined in system_prompt.py and enforced at the harness level:

Mandatory search — for anything current, recent, or version-dated, Loki must call web_search before answering. If it doesn't, the harness detects it and forces a retry.

Grounded — when search results are present, Loki answers only from the snippets, citing the source URL.

Opinionated — picks a side when asked "X or Y"; doesn't hedge with "it depends on your use case."

Honest — says "I don't know" when it doesn't. Prefixes guesses with guess:.

Plain — short answers, no markdown theater, no preamble or postamble.

The Modelfile carries the same temperature, top_p, and num_ctx values. The default brain is qwen2.5-7B-instruct, but the harness is model-agnostic — swap the FROM line in the Modelfile and rebuild.

08 — Quick Start
setup bash 
# Prerequisites: Python 3.9+, Ollama installed and running
  # Pull the base model
  ollama pull qcwind/qwen2.5-7B-instruct-Q4_K_M

  # Clone & install
  git clone https://github.com/0bsh3ll/loki.git && cd loki
  pip install -r requirements.txt

  # Build the Loki model in Ollama
  ollama create loki -f Modelfile

  # Run tests (no Ollama needed — 139 tests)
  python tests/test_tools.py

  # Launch
  python loki.py

Total dependencies: requests and ddgs. Everything else is Python standard library. No frameworks, no langchain, no vector databases. The entire agent loop is ~200 lines.

10 — Limitations & What's Next

The biggest limitation is the 7B model itself — it's fast and private but it hallucinates on complex multi-step reasoning. The harness mitigates this for factual queries (forced search + grounding), but it can't fix reasoning failures. Bigger models (13B, 70B) through Ollama are a drop-in upgrade if you have the hardware.

There's no sandboxing — a tool can touch anywhere the process can. The edit_file tool in particular has no guardrails beyond the model's judgment. For now this is intentional (it's a local tool for local use), but a confirmation step before destructive actions is the obvious next feature.

No multi-modal support yet. Images, PDFs, and audio are all on the roadmap once Ollama's vision model support stabilizes.

⚠️
There is no sandboxing. Tools execute with the same permissions as the Python process. Don't point Loki at directories you can't afford to have modified by a 7B model with opinions.
